# Codex sandbox runtime preflight

Use this when the triage runs inside a managed command sandbox. An `Operation not permitted` error from ADB's local server or a `permission denied` Docker socket can be imposed by the task sandbox. It is not, by itself, evidence that ADB or Docker is absent or broken.

1. Locate the actual binaries, including `$ANDROID_HOME/platform-tools/adb`, `$ANDROID_HOME/emulator/emulator`, and `$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager` when they are absent from `PATH`. Check `adb version`, `docker version`/`docker info`, and SDK package revisions separately. If socket creation fails in the sandbox, retry that same ADB or Docker diagnostic through the available approval/escalation path. Record the sandboxed and escalated outcomes. Do not ask for broad host access or treat an approved diagnostic as permission to install an APK on the host.
2. Keep a project-local SDK and AVD when the ordinary home directory is read-only. Set `ANDROID_HOME` to the SDK root and `ANDROID_USER_HOME`, `ANDROID_EMULATOR_HOME`, and `ANDROID_AVD_HOME` to writable, case-local directories. Verify the AVD `.ini` and writable disk paths before boot. Use an exact stable Google system image for the manifest target API; record its revision and hashes. A system image's ABI must match the delivered native split set. Reacquire a compatible split set if needed; an ARM64-only split is not made installable by selecting an x86_64 image.
3. Check `emulator -accel-check`, `/dev/kvm`, and CPU `vmx`/`svm` exposure in the **analysis VM**. If KVM is unavailable, a bounded no-APK boot test with documented software emulation may diagnose feasibility, but it is very slow and unsupported by Google. Require `sys.boot_completed=1` and package-manager responsiveness before treating the emulator as usable. A process that stays alive or an ADB server with no device is not a successful boot.
4. Verify Docker with a narrow, no-network, read-only test container after confirming daemon access. A host Docker daemon test proves only Docker availability. The Tor/Privoxy gateway for a full dynamic run must still start inside the disposable analysis VM after Android boot and must pass the fail-closed routing checks in [dynamic-run.md](dynamic-run.md).
5. Treat these as separate gates: task socket permission; SDK/image/AVD installation; emulator boot; compatible APK splits; verified disposable-VM boundary; Android egress policy; guest-side gateway. Record each gate's status and exact evidence. Do not let a successful ADB or Docker diagnostic erase a failed VM, boot, or network gate.

For a clean ADB check, use an unused server port and run `adb -P <port> devices -l`; a blank device list means the server works but no device is connected. For a Docker check, use `docker info --format '{{.ServerVersion}}'`, then a no-network test container. In a full dynamic run, run ADB and Docker inside the same verified analysis VM; grant only the task access required to reach those guest-local sockets.
